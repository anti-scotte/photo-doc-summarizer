技术创新

30%
CORE 01

三层弹性降级架构

任何一层挂掉，都照样出结果。这不是容错补丁，而是整个系统的骨架。

L1
本机大模型（Ollama）
启动与每次摘要前真实探测 /api/tags，确认已装模型才启用； 指定模型不存在时逐个尝试其他候选模型。
5 – 24 秒
L2
离线 TextRank 引擎
jieba 分词 + TextRank 词权重 + MMR 去重选句。 没装 Ollama、连不上、超时、格式错误，全部落到这一层，纯 CPU 毫秒级。
毫秒级
L3
规则正则兜底
五栏由标点与标记词切分；即使兜底引擎也异常，仍返回最小可用结果。 没有任何一条代码路径会把异常抛给用户。
毫秒级

接口永远返回结构完全一致的合法五栏 JSON， 前端不需要为"降级了"写第二套渲染逻辑；页面顶部与 engine_used 字段让当前引擎随时可验证。

CORE 02

五栏强约束提取

用规则把模型拉回真实。存疑栏是对抗大模型幻觉的机制，不是装饰。

栏位约束
·讲了什么1–3 条，只描述内容范围
·结论作者的判断与最终结论
·关键数字必须原样抄自正文并带单位，禁止换算与推算
·待办写清"谁、在什么时候、做什么"
·存疑 只写正文确实缺失或含糊的地方；没有就给空数组

提示词里写了硬规则："只依据正文，不许编造数字、人名或结论；数组宁可为空也不要凑数。" 模型找不到结论时没有"编一段填满版面"的余地 —— 空下来的栏必须在存疑栏解释原因。离线模式下这条逻辑由规则保证， 某栏为空时自动写入"正文没有明确的结论性表述""正文里没有出现可核实的数字"等具体说明。

最终输出不是"看起来像摘要"，而是每条都能溯源、每栏都有依据。 离线模式下数字栏直接切原句，每一句都能回查原文。

02

场景落地

30%

合同、内部报告、涉密材料不允许上传任何第三方服务器；内网机房、保密单位、出差现场根本没有公网。 云端 AI 摘要在这些场景里直接出局。

真实痛点本项目的解法
部署成本高解压即用：双击 run.bat，自动建环境 → 装依赖 → 起服务 → 打开浏览器
没有 GPU全部走 CPU：OCR 用 ONNX Runtime CPU Provider，模型仅十几 MB
不能联网装完依赖即可全程断网运行；支持 vendor/ 目录离线安装
机密文件只绑 127.0.0.1，代码级硬闸拒绝非本机地址；原件与记录 24 小时自动销毁
评委电脑没装 AI 环境三层弹性降级兜底，不需要为了试用去装 Ollama

03

开源治理

20%

项目采用 MIT License。但早期版本使用 PyMuPDF 解析 PDF， 而它是 AGPL-3.0 —— 其传染性会与 MIT 冲突，使项目无法在商业或闭源场景安全使用。

我们完整移除了该依赖，改用 pypdf（BSD-3-Clause）+ pypdfium2（Apache-2.0）： 文本层用 pypdf 抽取，识别到乱码时自动用 pypdfium2 二次抽取，扫描件则由 pypdfium2 渲染成图再交给 OCR。 功能不减、许可彻底干净。这是为合规主动做的重构，不是事后声明。

依赖许可用途
FastAPI / python-docx / jiebaMITWeb 服务、Word 解析、中文分词
uvicorn / pypdfBSD-3-ClauseASGI 服务器、PDF 文本抽取
PillowHPND图片解码与预处理
rapidocr-onnxruntime / pypdfium2Apache-2.0OCR、PDF 渲染

结论：全链路无 GPL / AGPL 传染风险，可与 MIT 协议共存并自由再分发。

长期发展

20%
01
支持更多文档格式（Excel / PPT）
接入 openpyxl 与 python-pptx：Excel 按工作表抽取表头与关键数据行，把「关键数字」栏对齐到单元格； PPT 抽取每页标题与要点。extract.py 已按扩展名分发，新增格式只加一个分支，不动上层逻辑。
