## 一、技术创新（30%）

### 1.1 三层弹性降级架构：任何一台破电脑上都跑得起来

大多数"AI 摘要"项目把全部希望押在大模型上：装不上就报错，模型没下载就崩，跑一半超时就 500。
本项目的核心设计是**任何一层挂掉都照样出结果**：

| 层级 | 引擎 | 触发条件 | 耗时 |
|---|---|---|---|
| **L1** | 本机大模型（Ollama） | 探测 `127.0.0.1:11434/api/tags`，**确认真的有模型**才启用 | 5 ～ 24 秒 |
| **L2** | 离线 TextRank 引擎 | 没装 Ollama / 连不上 / 模型缺失 / 调用超时 / 返回格式错误 | 毫秒级 |
| **L3** | 规则正则兜底 | 连 L2 都抛异常（极端情况）：五栏由标点与标记词切分，最后保底返回最小可用结果 | 毫秒级 |

三个关键细节：

- **探测不是"端口通了就行"** —— 真的去问 `/api/tags` 并确认至少有一个模型可用，避免误判后被 404 反复打脸
- **候选模型逐个试** —— 指定模型不存在时自动换下一个已装模型，全都不行才降级
- **降级不改变契约** —— 接口永远返回**结构完全一致的合法五栏 JSON**，前端不需要为"降级了"写第二套渲染逻辑

`summarize()` 的语义就是"**永远返回一个五栏结果**"：即使引擎构造失败、即使安全闸拒绝连接，也会落回离线引擎。
前端顶部会明示当前引擎，接口里的 `engine_used` 字段让"到底用了哪个引擎"随时可验证。

### 1.2 五栏强约束提取：用规则把模型拉回真实

通用摘要工具输出"一段看起来像摘要的文字"，无法验证、无法追责。本项目把输出**锁死为五栏**：

| 栏位 | 约束 |
|---|---|
| 讲了什么 | 1–3 条，只描述内容范围 |
| 结论 | 作者判断 / 最终结论 |
| 关键数字 | **必须原样抄自正文并带单位，禁止换算与推算** |
| 待办 | 写清"谁、在什么时候、做什么" |
| **存疑** | **只写正文确实缺失或含糊的地方；没有就给空数组** |

**存疑栏是这套设计的核心——它是用来对抗大模型幻觉的。**

- 提示词里写了硬规则：*"只依据正文，不许编造数字、人名或结论；数组宁可为空也不要凑数。"*
- 模型找不到结论时没有"编一段填满版面"的余地：**空下来的栏必须在存疑栏解释原因**
- 离线模式下这条逻辑由规则保证：某栏为空时，存疑栏自动写入
  "正文没有明确的结论性表述""正文里没有出现可核实的数字"等具体说明
- 数字栏在离线模式下直接切原句，**每一句都能回查原文**

结果不是"看起来像摘要"，而是**每条都能溯源、每栏都有依据**。

## 二、场景落地（30%）：解压即用，无网 / 无 GPU 也能处理机密文档

### 真实痛点

合同、内部报告、涉密材料不允许上传任何第三方服务器；内网机房、保密单位、出差现场根本没有公网。
云端 AI 摘要在这些场景里**直接出局**。

### 本项目的答案

| 痛点 | 解法 |
|---|---|
| 部署成本高 | **解压即用**：双击 `run.bat`，自动建环境 → 装依赖 → 起服务 → 打开浏览器 |
| 没有 GPU | 全部走 CPU：OCR 用 ONNX Runtime CPU Provider，模型只有十几 MB |
| 不能联网 | 装完依赖即可**全程断网运行**；支持 `vendor/` 目录离线安装 |
| 机密文件 | 只绑 `127.0.0.1`，代码级硬闸拒绝任何非本机地址；原件与记录 **24 小时自动销毁** |
| 评委电脑没装 AI 环境 | 三层弹性降级兜底，**不需要为了试用去装 Ollama** |

### 三个典型场景

- **会议记录整理**：白板照片、纸质签到、速记截图丢进去 → 直接出待办与责任人
- **学习笔记归档**：论文、教材章节批量处理 → 先看结论和数字，再决定要不要精读
- **机密文档处理**：合同、内部文件不出本机，断网环境下同样可用

## 快速开始

```bash
git clone https://github.com/anti-scotte/photo-doc-summarizer.git photo-doc-summarizer
cd photo-doc-summarizer
```

1. **双击 `run.bat`** —— 自动检查 Python（3.10–3.12）→ 建虚拟环境 → 安装依赖 → 启动服务 → 打开浏览器
2. **首次会下载约 150 MB 依赖** —— 走清华镜像，通常 2–5 分钟；窗口打印 `Installing dependencies...`，
   完成后显示 `dependencies ready.`。**第二次打开是秒启动**
3. **浏览器自动打开** `http://127.0.0.1:8000` —— 拖文件进去即可

> 任何一步失败都不会闪退：脚本停在窗口里显示英文原因，按任意键才关闭。

### 支持格式与实测速度

| 类型 | 扩展名 | 处理方式 |
|---|---|---|
| 图片 | `.png` `.jpg` `.jpeg` `.webp` `.bmp` `.tif` `.tiff` | EXIF 纠正 → RapidOCR 识别 |
| PDF（有文本层） | `.pdf` | pypdf 抽文本；乱码时自动换 pypdfium2 重抽，不跑 OCR |
| PDF（扫描件） | `.pdf` | pypdfium2 渲染 200 dpi → OCR（最多前 50 页） |
| Word | `.docx` | python-docx，正文 + 表格 |
| 纯文本 | `.txt` `.md` | 直读，UTF-8 / GBK 自动兜底 |

不支持：`.doc` / `.wps` 老格式、`.xlsx` / `.pptx`、加密 PDF、单文件超过 20 MB、超过 200 页。

| 场景 | 耗时 | 说明 |
|---|---|---|
| 200 字文档 · 离线提取引擎 | **约 4 秒** | 从拖入到五栏呈现的端到端时间 |
| 1000 字文档 · 本机大模型 | **约 24 秒** | 本机 7B 量化模型 CPU 推理 |
| 纯文本 150 字抽取 | 0.03 ～ 0.05 秒 | 纯计算时间 |
| A4 图片 OCR | 首次 7.3 秒 / 之后 1.4 秒 | 含 OCR 模型加载 |

> 测试环境：Windows / Python 3.12 / 无独立显卡 / 本机 Ollama `qwen2.5-coder:7b`。
> 端到端时间包含上传、后台排队与前端轮询刷新。

结果支持一键导出 `摘要_时间戳.md`（纯前端生成，不经过服务器）。

## 三、隐私与安全

| 承诺 | 实现方式 | 怎么验证 |
|---|---|---|
| 不上传任何外部服务 | 运行期零外部请求；调模型时有硬闸，非本机地址直接拒绝 | `GET /info` 看 `privacy.network` |

## 四、开源治理（20%）

### 许可合规：一次主动的技术整改

项目早期使用 **PyMuPDF** 解析 PDF，但它是 **AGPL-3.0** —— 其传染性会与本项目的 MIT 许可冲突，
导致整个项目无法在商业或闭源场景中安全使用。

我们完整移除了该依赖，改用：

- **pypdf（BSD-3-Clause）** —— 抽取 PDF 文本层
- **pypdfium2（Apache-2.0）** —— 把扫描页渲染成位图交给 OCR；中文 CID 字体混码时也用它二次抽取

> 功能不减、许可彻底干净。这是为合规主动做的重构，不是事后声明。

### 依赖许可矩阵

| 依赖 | 许可 | 用途 |
|---|---|---|
| FastAPI / python-docx / jieba / python-multipart | MIT | Web 服务、Word 解析、中文分词 |
| uvicorn / pypdf | BSD-3-Clause | ASGI 服务器、PDF 文本抽取 |
| Pillow | HPND（MIT-like） | 图片解码与预处理 |
| rapidocr-onnxruntime / pypdfium2 | Apache-2.0 | OCR、PDF 渲染 |
| onnxruntime / opencv / numpy 等传递依赖 | MIT / Apache-2.0 | 推理与图像处理 |

**结论：全链路无 GPL / AGPL 传染风险，可与 MIT 协议共存并自由再分发。**

## 五、Roadmap（未来规划）

### 1. 支持更多文档格式（Excel / PPT）

当前覆盖图片、PDF、Word、纯文本。下一步接入 `openpyxl` 与 `python-pptx`：

- **Excel**：按工作表抽取表头与关键数据行，把「关键数字」栏直接对齐到单元格
- **PPT**：抽取每页标题与要点，天然契合「讲了什么 / 结论」两栏
- 落地成本低：`app/extract.py` 已是按扩展名分发的单文件解析器，新增格式只加一个分支，不动上层

### 2. 引入多模态视觉大模型

当前图片走 OCR 再摘要，会丢失版面信息（表格结构、图表趋势）。计划引入**本地多模态模型**：

- 直接理解页面截图，跳过 OCR 的中间损耗
- 识别图表类型与趋势描述，补强「关键数字」与「存疑」两栏
- 仍然遵守硬约束：**只允许调用本机服务**；三层弹性降级不变（没有视觉模型时自动回到 OCR 路径）

### 3. 完善社区贡献指南

- 补充**开发者文档**：各层接口契约、五栏字段规范、降级链路的测试方法
- 增加**自动化测试**（`test_extract.py` / `test_summarize.py`）并接入 CI —— 当前 CI 只做语法检查
- 建立 **Issue 标签体系**与响应时限，补充 `CODE_OF_CONDUCT.md`
- 提供**样例文件包**，让贡献者一键复现三条处理链路

## 已知限制

- **OCR 对图像质量敏感**：模糊、倾斜、逆光、手写会掉识别率
- **表格会被打平**：Word / PDF 表格转成 `列 | 列` 纯文本，不保留结构
- **部分中文 PDF 需要二次抽取**：pypdf 遇到 CID 字体可能抽出乱码，自动改用 pypdfium2；都失败才走 OCR，会慢一些
- **扫描件只 OCR 前 50 页**，超出部分在正文里注明
- **离线引擎是"选句"不是改写**，语言连贯性不如大模型 —— 这是换取"任何机器秒级可用"的代价
- **超长文档**：只把正文前 5000 字送给大模型，超出部分结果里会给 warning
- **单机单实例**：SQLite + 线程池，不面向多人并发
